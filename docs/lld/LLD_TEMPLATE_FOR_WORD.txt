EXECUTIVE SUMMARY
================================================================================

The PSDB Layout V2 & V3 introduces bitmap-based sparse feature encoding to the
online feature store's permanent storage layer. This design reduces storage
footprint for datasets with missing or default-valued features through:

KEY FEATURES:
  - Bitmap Metadata: Optional per-feature presence indicator
  - Sparse Payload: Only non-default features are serialized
  - Compression Integration: Works alongside existing compression algorithms
  - Type Safety: Full support for all scalar and vector data types
  - Backward Compatibility: Layout V1 support maintained through versioning

EXPECTED BENEFITS:
  - 20-60% storage reduction for sparse feature sets
  - Minimal latency overhead for dense feature sets
  - Transparent handling of missing features via defaults

SCOPE:
  - 14 commits integrating bitmap-based sparse encoding
  - 42 files modified across serialization, deserialization, and storage
  - 5,187 insertions and 1,177 deletions from main branch

SERIALIZATION PIPELINE
================================================================================

OVERVIEW:

The serialization pipeline transforms in-memory feature data into a compact
byte format optimized for sparse data. It handles all scalar and vector types
with automatic bitmap generation for sparse encoding.

ENTRY POINT PATTERN:

// From persist.go - Feature persistence flow
func (h *Handler) persistFeatures(ctx context.Context,
                                  features map[string]interface{}) error {

    // 1. Create PSDB builder
    builder := NewPermStorageDataBlockBuilder()

    // 2. Set data and metadata
    builder.SetData(features[dataType])
    builder.SetNoOfFeatures(len(features))
    builder.SetDataType(dataType)

    // 3. Optional: Set bitmap for sparse encoding
    if shouldEnableSparseMode(features) {
        builder.SetBitmap(generateBitmap(features))
    }

    // 4. Serialize
    psdb := builder.Build()
    serialized, err := psdb.Serialize()

    // 5. Persist to storage
    return h.store.Set(featureKey, serialized)
}


SERIALIZATION STEPS:

Step 1: Type Detection
  Input: Feature data in container ([]float32, []int32, []bool, etc.)
  Output: Validated DataType enum
  [Detailed implementation: perm_storage_datablock_v2.go:serializeXXXV2()]

Step 2: Bitmap Generation (Optional)
  Input: Feature data, optional bitmap indicator
  Output: Bitmap byte array marking non-default features
  Size: (numFeatures + 7) / 8 bytes
  [Implementation: Handled in SetBitmap()]

Step 3: Header Construction
  Input: Metadata (schema version, expiry, layout, compression, datatype)
  Output: 10-byte header for Layout V2
  [Implementation: setupHeadersV2() and related functions]

Step 4: Type-Specific Encoding
  Input: Feature values, type-specific encoder
  Output: originalData buffer filled with encoded bytes
  Handlers:
    - serializeFP32AndLessV2() - Floating point types
    - serializeInt32AndLessV2() - Integer types
    - serializeUint32AndLessV2() - Unsigned integer types
    - serializeBoolV2() / serializeBoolVectorV2() - Boolean types
    - serializeStringV2() / serializeStringVectorV2() - String types

Step 5: Compression
  Input: Encoded data, compression type
  Output: Compressed bytes (or original if compression ineffective)
  [Implementation: encodeData() and compression.Encoder interface]

DATA FORMAT SPECIFICATION
================================================================================

HEADER LAYOUT (10 bytes for Layout V2):

Byte 0-1:     Feature Schema Version (uint16)
              Bits [15:0] = Schema Version number
              Byte Order: System byte order

Byte 2-6:     Expiry Timestamp (40 bits = 5 bytes)
              Encoded as 5 bytes in system byte order
              Can be decoded as uint64 with EncodeExpiry()
              Checked with IsExpired() for cache validation

Byte 7:       Layout, Compression, and DataType High Bit
              Bits [7:4] = Layout Version (4 bits)
                           Values: 0=V1, 1=V2, 2=V3, 3=Reserved
              Bits [3:1] = Compression Type (3 bits)
                           Values: 0=None, 1=TypeA, 2=TypeB, etc.
              Bit [0:0]   = DataType High Bit (1 bit)
                           MSB of 5-bit DataType enum

Byte 8:       DataType Low 4 Bits and Bool Index
              Bits [7:4] = DataType Low 4 Bits (4 bits)
                           Combined with byte 7 bit 0 for full enum
              Bits [3:0] = Bool DType Last Index (4 bits)
                           Only meaningful for Bool data types
                           Marks position of last set bit in last byte

Byte 9:       Layout V2+ Metadata (Bitmap Presence)
              Bit [0:0]   = Bitmap Present Flag (1 bit)
                           1 = Bitmap section present
                           0 = No bitmap (Layout V1 style)
              Bits [7:1] = Reserved (7 bits)
                           Must be zero; reserved for future use

TOTAL: 10 bytes for Layout V2 (9 bytes header + 1 byte metadata)


PAYLOAD LAYOUT (Layout V2):

If BitmapMeta & 0x01 == 1 (Bitmap Present):
    ┌─────────────────────────────────────────┐
    │ Bitmap Section                          │
    │ Size: (numFeatures + 7) / 8 bytes       │
    │ Bit i = 1 if feature i is present       │
    │ Bit i = 0 if feature i uses default     │
    │ Byte order: MSB = feature 0 in byte     │
    └─────────────────────────────────────────┘
    ┌─────────────────────────────────────────┐
    │ Dense Payload                           │
    │ Only non-default features (sparse)      │
    │ Order: ascending by feature index       │
    │ Type-specific encoding per feature      │
    └─────────────────────────────────────────┘

Else (BitmapMeta & 0x01 == 0 - No Bitmap):
    ┌─────────────────────────────────────────┐
    │ All Features (dense)                    │
    │ Layout V1 style (all features present)  │
    │ Type-specific encoding per feature      │
    └─────────────────────────────────────────┘


DATA TYPE ENCODING TABLE:

DataType     | Bytes  | Variants       | Encoding Method
=================================================================
FP8E4M3      | 1      | Scalar, Vector | float8.FP8E4M3FromFP32Value()
FP8E5M2      | 1      | Scalar, Vector | float8.FP8E5M2FromFP32Value()
FP16         | 2      | Scalar, Vector | float16.Fromfloat32() + PutUint16()
FP32         | 4      | Scalar, Vector | math.Float32bits() + PutUint32()
FP64         | 8      | Scalar, Vector | math.Float64bits() + PutUint64()
Int8         | 1      | Scalar, Vector | Direct byte cast
Int16        | 2      | Scalar, Vector | PutUint16(uint16(value))
Int32        | 4      | Scalar, Vector | PutUint32(uint32(value))
Int64        | 8      | Scalar, Vector | PutUint64(uint64(value))
Uint8        | 1      | Scalar, Vector | Direct byte assignment
Uint16       | 2      | Scalar, Vector | PutUint16(value)
Uint32       | 4      | Scalar, Vector | PutUint32(value)
Uint64       | 8      | Scalar, Vector | PutUint64(value)
Bool         | 1 bit  | Scalar, Vector | Bit-packed in bytes
String       | Var    | Scalar, Vector | 2-byte length + data (Pascal)


EXAMPLE SERIALIZED BYTES (Float32 Scalar, No Compression):

[Byte 0-1]   0x0001              (Schema version = 1)
[Byte 2-6]   0xABCDEF0102        (Expiry timestamp)
[Byte 7]     0x24                (Layout=0x2, Compression=0x1, FP32 high=0)
[Byte 8]     0x30                (FP32 low=0x3, Bool index=0)
[Byte 9]     0x00                (No bitmap)
[Byte 10+]   (compressed/encoded feature values)

CRITICAL FIXES FROM PR #266:

1. Bitmap Bounds Checking
   Issue: Array access without validation could panic
   Fix: Add byteIdx >= len(bitmap) check before access
   Locations: countSetBitsBefore(), skipStringVectorsInDense(),
             GetNumericVectorFeature(), GetBoolVectorFeature()

2. Bool Vector Serialization
   Issue: Partial byte with unfilled bits was dropped
   Fix: Include partial byte if shift != 7
   Location: serializeBoolVectorV2()

3. Type Mismatch
   Issue: FP32Vector decoder using FP16Vector
   Fix: Change to ByteOrder.Float32Vector
   Location: byteorder/system.go

[Code examples for common operations]

EXAMPLE 1: Serializing Float32 Features

  // Create builder
  builder := NewPermStorageDataBlockBuilder()

  // Set up data
  features := []float32{1.5, 2.5, 3.5}
  builder.SetData(features)
  builder.SetNoOfFeatures(len(features))
  builder.SetDataType(DataTypeFP32)

  // Optionally set bitmap for sparse encoding
  bitmap := []byte{0xFF}  // All features present
  builder.SetBitmap(bitmap)

  // Serialize
  psdb := builder.Build()
  serialized, err := psdb.Serialize()

  // Store result
  err = storage.Set("feature_key", serialized)


EXAMPLE 2: Deserializing with Bitmap

  // Read serialized data
  data, err := storage.Get("feature_key")

  // Deserialize
  psdbBlock, err := DeserializePSDB(data)

  // Check layout version
  layout := psdbBlock.GetLayoutVersion()

  if layout == 2 {
    // Cast to Layout 2 for bitmap operations
    layout2 := psdbBlock.(*DeserializedPSDBLayout2)

    // Extract feature at position 0
    feature, err := layout2.GetNumericScalarFeature(0, 3, defaultValue)
  }
